# 1030 实虚词二审预览页搜索与词类标识设计

## 目标

优化 `sql/1030实虚词二审/word-student-preview-1030-second-review.html` 的学生端预览交互：支持按原词精确搜索，并在同一原词同时包含实词、虚词释义时，在释义选项卡上显示清晰的词类标识。

## 已确认需求

- 搜索区域增加原词输入框和“搜索”按钮。
- 输入后按回车或点击按钮才执行搜索，不做实时过滤。
- 搜索只匹配 `word` 原词字段，采用精确匹配；不搜索释义、原句、来源、译文等字段。
- 搜索为空时恢复全部词条；无匹配时显示空结果提示。
- 只有同一个原词同时存在 `wordClass=1`（实词）和 `wordClass=2`（虚词）时，才显示词类标识。
- 词类标识放在释义选项卡位置：实词使用醒目橙黄色，虚词使用蓝紫色。
- 单一词类原词不显示词类标识，避免无必要的信息重复。
- 修改预览生成脚本并重新生成二审预览页，避免手工改 HTML 后再次生成时丢失。

## 方案

在 `tools/update_yuwen_word_preview.js` 中完成页面逻辑改造：

1. 在筛选区域加入表单式搜索控件，监听表单 `submit`，因此点击按钮和按回车走同一条查询路径。
2. 增加 `searchWord` 状态。提交时对输入值做首尾空白清理，并以 `row.word === searchWord` 参与现有版本、分册、篇目和词类筛选；空字符串不限制原词。
3. 在词条分组阶段计算 `mixedWord`：同一 `word` 的记录中是否同时存在实词和虚词。释义选项卡仅在 `mixedWord` 为真时渲染词类 badge。
4. 为释义选项卡增加两种主题样式：`.sense-class-real` 使用橙黄色，`.sense-class-virtual` 使用蓝紫色；保留现有选项卡的布局和切换行为。
5. 重新生成 `word-student-preview-1030-second-review.html`，保证页面内嵌 records 数据继续来自二审三张 SQL。

## 交互与边界

- 搜索不会修改 SQL 数据。
- 搜索与已有筛选条件叠加；例如搜索“而”后再选择“虚词”，只展示同时满足两者的数据。
- 原词搜索区分原词字段的完整值，不把“而”匹配到释义或例句中的其他文字。
- 由于当前原词均为单字，输入多字文本通常无匹配，但仍按精确值处理。
- 类型标识只出现在释义选项卡，不在释义内容面板重复显示。

## 验证

- 运行预览生成脚本，确认生成成功且记录数与二审 SQL 的 sense 数一致。
- 用页面脚本静态检查：输入“而”可精确命中“而”，输入“而”不命中其他例句包含“而”的词；空输入恢复全量。
- 检查同时含实词和虚词的原词显示两种不同颜色 badge，单一词类原词不出现 badge。
- 校验预览 records 的词义、原句、来源、译文仍与 SQL 一致。
