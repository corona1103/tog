# 语文积累本：高中必修上册实虚词内容与学生端预览设计

- 日期：2026-09-18
- 范围：高中教材实虚词首轮内容生产与学生端人工预览
- 状态：设计已确认，待实施

## 1. 目标

为高中部编版必修上册《芣苢》《劝学》《师说》生产一批可直接导入研发数据库的实词/虚词内容，并提供独立的学生端预览页面，便于人工审核词义、例句、翻译和题目关系。

首轮采用核心词口径：优先覆盖教材注释、高中常见义和容易混淆的课内用法，不穷举三篇全文所有虚词和实词。

## 2. 教材关系

沿用现有 `edu_chn_poem_catalog` 目录中的固定 ID：

- 版本：`00b6bf17df4345109f570bf0273705f3`，名称为“部编版”。
- 分册：`1a84b7ac1ef9d3b5d624d994c88f239a`，名称为“高中必修上册”。
- 《芣苢》：单元 `a738eb5ca76659a9e8f67ef5659434d4`，名称为“第一单元（课内）”。
- 《劝学》《师说》：单元 `a453b281b71fd478be1d9d791307bf5c`，名称为“第五单元（课内）”。

用户提供的两张业务表没有教材关联字段，因此教材关系单独落到 `edu_chn_word_catalog`，字段沿用附件目录的版本/分册/单元信息，并以 `sense_id` 关联 `edu_chn_word_sense.id`。同时保留 `word_book_scope.csv` 作为表格核对文件。

## 3. 内容数据

### 3.1 词义例句

文件 `sql/edu_chn_word_sense.sql` 对应 `edu_chn_word_sense` 表。每条记录表示一个“原词 + 一个词义 + 一个课内例句”，同一个原词的多条词义和例句通过相同 `word` 聚合到词卡中。

字段规则：

- `word_class`：1 为实词，2 为虚词。
- `word`：原词；`pinyin`：现代汉语拼音读音。
- `meaning`：面向高中生的简明词义/用法，必要时标注词性或特殊用法。
- `example`：单句原文，使用 `<b>词</b>` 标记目标词；SQL 中使用合法转义。
- `source`：例如“部编版｜高中必修上册｜第五单元（课内）｜《劝学》”。
- `example_trans`：与该单句对应的准确翻译。
- 初始 `status=0`、`is_del=0`，由研发或运营审核后上架。

### 3.2 题目

文件 `sql/edu_chn_word_question.sql` 对应 `edu_chn_word_question` 表。每个 `sense_id` 固定生成两条题目：

- `question_type=1`：词义选择。题干引用该条原文例句，选项为正确词义和三个同类混淆项。
- `question_type=2`：辨析选择。题干为“下列句子中加点词的意义和用法与例句相同的一项是”，选项为一个同义/同用法句子和三个不同义/不同用法句子。

`options_json` 格式固定为 `[{
  "content": "选项文本",
  "correct": true
}]`，每题只有一个 `correct=true`。初始 `status=0`、`is_del=0`。

### 3.3 教材映射

文件 `sql/edu_chn_word_catalog.sql` 创建并写入 `edu_chn_word_catalog` 关系表；`word_book_scope.csv` 提供同一份关系的表格核对版本。字段至少包含：`version_id,version_name,volume_id,volume_name,unit_id,unit_name,chapter,word_class,word,sense_id`。每个 `sense_id` 都必须能在词义 SQL 中找到，映射中的篇目限定为三篇目标课文。

## 4. 学生端预览

文件 `demo/yuwen/accumulation/word-student-preview.html` 为独立、无后端依赖的学生端预览页面。

### 4.1 词卡列表

- 固定横屏学生平板外壳，延续现有积累本 Demo 的蓝绿视觉风格。
- 顶部显示“部编版 · 高中必修上册”。
- 支持“全部 / 实词 / 虚词”和篇目筛选。
- 原词卡聚合展示拼音、全部词义、词性、课内例句、翻译和来源。
- 每个原词提供“查看题目”按钮。

### 4.2 题目预览

- 点击“查看题目”打开侧边抽屉或弹层，不跳离当前词卡上下文。
- 按当前原词的全部例句逐条展示。
- 每条例句下固定展示词义选择和辨析选择两种题型。
- 仅做可读性预览，不实现提交、判题、审核、账号和后端请求。
- 长例句和长选项可滚动，窄视口显示横屏提示，不重排为竖屏。

## 5. 质量与验证

实施后进行以下检查：

1. 解析 SQL，确认词义记录、题目记录和 `sense_id` 外键关系数量一致。
2. 检查每个 `sense_id` 恰好有 `question_type=1/2` 各一条。
3. 解析全部 `options_json`，确认 JSON 合法、每题恰好一个正确项、选项数量为四个。
4. 检查教材映射中的所有 `sense_id` 都存在，固定版本/分册/单元 ID 与附件一致。
5. 在浏览器打开独立 Demo，验证筛选、查看题目、关闭弹层和长内容滚动。
6. 对三篇课文抽查代表性实词、虚词、翻译和辨析选项，确认来源和语义没有错配。

## 6. 不纳入范围

- 不修改用户现有的 `index.html` 主 Demo 数据。
- 不修改用户提供的两张词义/题目表结构；教材关系使用本次新增的 `edu_chn_word_catalog` 表。
- 不实现线上审核流程、提交判题、学习记录和后端接口。
- 不扩展到《沁园春·长沙》《插秧歌》或必修上册其他篇目。
