# 语文实虚词内容质量修订设计

## 目标

统一修订高中与初中语文积累本实虚词数据：所有 `meaning` 增加词性前缀；逐条检查空白例句并尽可能补齐原文与译文；在学生端预览页增加可复制的审核定位信息。

## 数据方案

不新增数据库字段，沿用现有 `edu_chn_word_sense.meaning` 字段，统一使用 `<词性>释义` 格式，例如 `<副>适逢；恰巧遇上`。生成脚本中的词条源数据、统一 SQL 和预览数据保持同一格式。

词性采用常见文言文标注：名、动、形、副、介、连、代、助、语气、兼词、通假、意动、使动、数、量等。涉及通假、活用时，在词性后保留必要的语法说明，不改变原有释义内容。

## 空例句处理

以当前项目中的高中、初中词条源数据和篇目原文为第一来源，逐条检查 `example`、原词高亮和 `example_trans`。能够确认的词补入原句、译文并生成题目；当前资料无法确认的词保留 `NULL` 和草稿状态，输出独立的待补清单，避免编造课文原文。

校验项包括：空例句数量、非空例句是否包含原词高亮、非空例句是否有译文、空例句是否被错误生成题目、题型一是否 4 项且首项正确、题型二是否 2 项且首项正确。

## 预览交互

每条例句后保留现有“查看题目”或“例句积累”状态，并增加“复制”按钮。复制内容包含：`sense_id`、原词、词义、篇目、原句、题型一 `question_id`、题型二 `question_id`。无题目的例句复制时使用“无题目”标识。优先使用 Clipboard API，失败时使用兼容性文本域回退，并通过按钮文案短暂反馈“已复制”。

## 交付物

- 统一词义、题目、教材关系 SQL
- 词义生产与校验脚本
- 空例句待补清单
- 学生端预览页
